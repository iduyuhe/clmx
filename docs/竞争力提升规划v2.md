# CLMX 竞争力提升规划 v2

> **基于 2026-07-15 11:07 竞争力评价**
> **当前定位**: 从「能交付」到「第一个客户签单」

---

## 核心判断

CLMX 目前的功能完备度已经超过了"PoC 被 pass"的临界点。下一步的关键不是加更多功能，而是**消除客户签单前最后的顾虑**。

三类顾虑：
1. **「数据锁死怎么办？」** → 需要数据导出
2. **「怎么集成到我们系统？」** → 需要 API 文档 + 示例
3. **「跑起来稳不稳？」** → 需要运维监控 + 健康仪表盘

---

## 优先事项

### P0 · 数据导出（消除"vendor lock-in"顾虑）

客户问的第一句话往往是"万一以后不用了，数据能拿走吗？"

| 导出内容 | 格式 | 实现方式 |
|---------|------|---------|
| 设备清单 | CSV | GET /api/devices/export?format=csv |
| 传感器数据 | CSV（按时间范围） | GET /api/sensor-data/export?sensorId=X&start=... |
| 模型文件 | tar.gz（checkpoint + model_meta） | GET /api/models/:id/versions/:vid/export |
| 训练结果 | JSON（含指标） | 复用现有 API + 批量下载 |
| 全量数据 | 多文件 zip | 后台打包后下载 |

工作量：前后端共半天。

### P1 · Swagger API 文档（消除"集成难度"顾虑）

| 项目 | 说明 |
|------|------|
| 工具 | swagger-jsdoc + swagger-ui-express |
| 覆盖 | auth / devices / sensors / training / inference / models |
| 产出 | 交互式 API 浏览器，在线调试 |
| 工作量 | 半天（标注 JSDoc 路由） |

### P2 · 部署健康仪表盘（消除"运维能力"顾虑）

在 UI 中增加系统健康页面：
- PM2 进程状态（在线/重启次数/内存）
- API 调用统计（延迟 p50/p95/error rate）
- 数据库连接状态
- 存储用量趋势

工作量：1 天。

---

## 执行建议

先做 P0（数据导出），再做 P1（API 文档），因为：

1. **数据导出**是客户采购流程中的"必须答"问题
2. 导出功能在 PoC 阶段就能展示，不需要等客户真正部署
3. 导出 CSV 的接口可以在 Swagger 文档中一并呈现
