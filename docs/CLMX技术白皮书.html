01摘要

CLMX 是一套面向工业互联网的垂类 AI 模型训练、推理与能力开放平台。它把"为某台设备训练一个异常检测模型"这一手工作坊式任务，抽象为一套可复用、可编排、可对外开放的模型工厂。

平台以"工业设备预测性维修"为首个落地外壳，但底座是一套通用的模型生产与运营系统：内置无监督时序异常检测、零依赖中文文本分类两类训练-推理同构引擎，并围绕"让平台自身具备一定智能"的目标，落地了半智能体闭环（自然语言交互 → 自动基线 → 异常自动处置 → 训练结果自动解读）。

在接入侧，CLMX 引入 AI 原生接入生成器：从设备文档/样本/描述自动抽取测点、生成物模型与零依赖采集驱动，并就地自测；在开放侧，CLMX 以北向 MCP（Model Context Protocol）能力底座把既有 API 封装为 10 个可被外部 AI 智能体直接编排的工具。两个方向共同支撑"护城河"——训练-推理同构 + 零依赖边缘 JS 推理，使模型无需深度学习框架即可在边缘运行。

本白皮书阐述 CLMX 的定位、架构、四大核心能力、机器学习管线、关键技术决策、安全模型与开源路线，供技术决策者、集成商与贡献者参考。

02背景与行业挑战

2.1 工业预测性维修的痛点

工业设备的非计划停机代价高昂。传统"定期保养"要么过度维护、要么漏检。用数据驱动的方式做预测性维修（PdM）是公认方向，但落地长期卡在四道坎：

🧩

接入即地狱

不同品牌、协议、点位命名千差万别。每接一台设备都要写一遍采集驱动与物模型，工程量大、易出错、难复用。

🏷️

标注稀缺

异常样本极少且代价高。监督学习在工厂现场几乎拿不到足量标注，模型还没训练就已"饿死"。

🖥️

边缘跑不动

深度学习框架体积大、依赖重，难以部署到网关/边缘节点；而把推理全压回中心又带来时延与带宽问题。

🧱

平台不智能

多数工具只是"仪表盘 + 阈值告警"，告警出来仍要人去理解、去处置、去复盘，平台本身不参与决策闭环。

2.2 现有方案的三大短板

  • 偏向"单个模型"而非"模型生产体系"：多数 PdM 方案交付的是一个训练好的模型，缺乏把建模过程产品化、可重复、可运营的能力。
  • 偏向"挂个问答机器人"而非"能力开放"：把 AI 等同于聊天入口，没有把平台能力以标准化协议对外开放，难以被外部智能体编排。
  • 重中心、轻边缘：推理强依赖中心侧 GPU/框架，边缘侧只能做透传，失去"就近智能"的弹性。
CLMX 的设计出发点，不是再做一只"更聪明的仪表盘"，而是把上述四道坎一次性工程化消化：接入自动生成、训练免标注、推理零依赖、平台半自主。

03平台定位与设计哲学

3.1 CLMX 是什么：模型工厂，而非单个模型

一个容易混淆的概念需要厘清：

概念是什么CLMX 的角色
垂类模型针对某场景训练出的一个具体模型（如空压机振动异常检测）CLMX 产出 的对象
智能体（Agent）调用模型自主完成任务的角色CLMX 的使用者 / 编排者
CLMX模型工厂 + 推理服务 + 能力开放平台训练、托管、开放模型的底座

对外话术："面向工业互联网的垂类 AI 模型训练与推理平台"。平台生产垂类模型，智能体调用模型——二者通过北向 MCP 衔接。

3.2 核心设计原则

零依赖优先

尽可能用纯 JS / 标准库实现训练与推理，避免引入重型框架，保证边缘可跑、依赖可控。

训推同构

训练与推理使用同一套代码与数值逻辑，消除"训练用 Python、上线用另一套"的偏差与维护成本。

多租户隔离

行级数据隔离，所有 CRUD 强制带 tenantId，平台即服务（SaaS）交付。

3.3 HubPort 思想融合

CLMX 评估了"HubPort（AI 原生物联网平台）"的思想，结论为融思想、不搬产品。采纳其四个核心思想，并明确不学之处：

思想采纳（落到 CLMX）
T1 · AI 原生接入接入生成器：文档/描述 → 自动生成物模型 + 采集驱动 + 自测
T2 · 创建时 AI、运行时零 AI驱动在"创建时"由 AI/启发式生成，运行时纯 JS 零依赖执行（与护城河同构）
T3 · 能力资产化IngestSpec / IngestAsset 模型 + 发布市场 + 一键复用（reuseCount）
T4 · 北向开放自实现 MCP 底座，把平台 API 封装为 10 个标准工具供外部智能体编排
红线："AI 原生 ≠ 挂个问答机器人"。CLMX 不学 HubPort 的产品广度（680+ 功能/全栈 IoT）、多语言运行时（保持零依赖 JS）、受控 CLI 直跑 shell（选 MCP 标准协议替代）。

04整体架构

CLMX 采用前后端分离、分层清晰的服务架构。后端以 Express + Prisma 提供服务，前端以 React + TypeScript + Tailwind 构建；接入层同时支持 MQTT（aedes）与 AI 原生接入端点；模型层由 Python worker（CPU 模式）承担训练，推理则下沉到零依赖 JS。

05核心能力一：半智能体闭环

CLMX 把自身智能化成熟度目标定在第 3 档"半智能体"：具备感知—决策—处置闭环，但不做全自主智能体（会与零依赖边缘底座冲突）。四项能力协同形成闭环：

图 2 · 半智能体闭环：自然语言入口 → 自动基线 → 异常处置（核心）→ 训练解读

① 自然语言交互入口

把"看板操作"升级为"语言操作"。用户用中文描述意图（如"给 1 号冷却水泵生成上周健康分"），平台解析后调用对应能力。该入口同时经北向 MCP 暴露为 clmx_nl_command，便于外部智能体复用。

② 自动基线与健康评分

平台基于历史数据自动计算各测点的基线与健康分，告警阈值不再是人工拍脑袋。健康分 < 60 时通过 Notification + AlertChannel 自动推送，无需人工盯盘。

③ 异常自动处置闭环（核心）

检测到异常后，平台可自动触发处置动作链（通知、派单、联动、必要时触发再训练），形成"感知—决策—处置"闭环。这是 CLMX 区别于"仪表盘 + 阈值"的关键。

④ 训练结果自动解读

训练/推理结束后，平台自动产出可读解读（指标、异常区间、建议），降低使用门槛，也让闭环可解释、可审计。

半智能体并不追求"完全自主"。它在人设定的边界内闭环运转，把重复、可程序化的决策交给平台，把价值判断留给用户——这正是工业场景所需的可控智能。

06核心能力二：AI 原生接入生成器

6.1 痛点：接入即地狱

工业现场每接一台设备，都要人工写采集驱动、定义物模型、对齐点位命名。CLMX 的接入生成器把这一过程自动化：

图 3 · 接入生成器流水线：从非结构化输入到可运行、可复用资产

6.2 测点提取优先级

生成器按可信度从高到低尝试，命中即停：

  1. 结构化 JSON：直接解析点位定义；
  2. 样本数据推断：从采集样本反推测点类型与单位；
  3. 描述启发式词典：用"温度/压力/振动/转速/电流"等中文工业词典从文本抽取；
  4. 可选 LLM（env 门控）：仅在配置 LLM 密钥时启用，且不引入任何 npm 依赖，纯 HTTP 调用。

6.3 物模型与零依赖驱动生成

提取出测点后，生成标准物模型与一段零依赖 JavaScript 采集驱动 collect(ctx)。驱动在"创建时"由 AI/启发式生成，在"运行时"以纯 JS 执行——这正是 HubPort T2 思想的落地：创建时 AI，运行时零 AI。

6.4 沙箱自测与运行时

生成后用 new Function 沙箱执行驱动，验证其产出有限数值；通过后即可发布到资产市场。运行时端点接收驱动并执行，将结果写入 SensorData，与既有 MQTT 遥测端点共存于 /api/ingest。

代码片段：生成的采集驱动示例

// 由接入生成器产出（零依赖，运行时纯 JS 执行）
function collect(ctx) {
  const t = Date.now();
  return [
    { point: 'temperature', value: sim(ctx, 'temperature', 65, 8), ts: t },
    { point: 'vibration',  value: sim(ctx, 'vibration',  2.3, 0.6), ts: t },
    { point: 'current',    value: sim(ctx, 'current',   12, 1.5), ts: t }
  ];
}
资产化：生成结果沉淀为 IngestSpec（需求草稿）/ IngestAsset（版本链，unique(specId, version)，含 published、reuseCount、driverCode、thingModel）。一键 apply 即可为设备自动建立传感器并投入运行。

07核心能力三：北向 MCP 能力开放

7.1 为什么是 MCP

平台的真正价值在于"被使用"。CLMX 选择 MCP（Model Context Protocol）作为北向开放标准，而非自建 CLI 直跑 shell——外部 AI 智能体可据此直接编排 CLMX 能力，平台从"被点击"升级为"被编排"。

7.2 零依赖 JSON-RPC 实现

MCP 服务自实现 JSON-RPC 2.0 over NDJSON（不引入官方 SDK），stdio 传输，日志走 stderr 以免污染协议流。鉴权支持 CLMX_API_TOKEN 直传或 CLMX_API_EMAIL/PASSWORD 自动登录。退出逻辑为"输入流关闭后等待在途请求完成再退出"，保证不丢请求。

08核心能力四：多租户 SaaS 底座

CLMX 以"平台即服务"方式交付，所有数据按租户隔离。

行级隔离（不可违反的约束）

  • 所有 CRUD 的 where 必含 tenantId: req.tenantId；
  • 操作子资源时先联查父资源验归属，杜绝越权；
  • req.tenantId / req.userRole 由 authMiddleware 从 JWT 注入；
  • 预置数据 tenantId: null，查询时用 OR [tenantId=?, tenantId=null] 兼容。

增值能力

阶段 4 起已具备配额、计费、白标等 SaaS 增值能力，使平台既能自运营，也能作为底座被集成商二次分发。

隔离是安全性的第一道防线。CLMX 把 tenantId 过滤作为路由层强制约定（而非业务代码自觉），从架构上消除"漏写条件导致跨租户泄露"的隐患。

09机器学习管线

9.1 无监督异常检测

采用 Autoencoder / 隔离森林 等无监督方法，免标注即可从正常工况数据中学习分布，对偏离进行打分。这直接回应了"标注稀缺"的工业现实——不需要异常样本也能上线。

9.2 零依赖中文文本分类

对设备工单、日志等中文文本，采用朴素贝叶斯实现，训推同构、纯 JS，不依赖任何 NLP 框架。关键词提取工具 clmx_keywords 即此能力的对外暴露。

9.3 训练-推理同构与边缘 JS 推理

训练（Python worker 负责重型拟合）与推理（零依赖 JS）共享同一套数值逻辑。推理侧不引入深度学习框架，因此可直接在边缘节点运行，实现"就近智能"，这是 CLMX 的核心护城河之一。

9.4 告警投递

Notification + AlertChannel 已上线：当健康分 < 60 时自动推送，并可按渠道配置（如企微、Webhook）。告警不是终点，而是"半智能体闭环"的触发信号。

10数据模型概览

核心实体（Prisma 模型）覆盖设备、模型、训练、接入资产与多租户边界：

模型职责
Device / Sensor / SensorData设备、测点、时序数据
AiModel / Dataset / DataVersion模型、数据集及其版本
TrainingJob / ModelVersion / TrainingLog训练任务、模型版本、训练日志
IngestSpec / IngestAsset接入需求草稿 / 版本化接入资产（含 driverCode、thingModel、reuseCount）
AlertRule / Notification / AlertChannel告警规则、通知与渠道
Tenant / User / Role多租户与 RBAC
删除顺序（FK 约束）：TrainingLog → ModelVersion → TrainingJob → DataVersion → Dataset → AiModel → Device。务必从最深子表起删，避免外键冲突。

11关键技术决策与权衡

决策取舍原因
BigInt 补丁（server.ts 开头）保留一段"看似多余"的补丁SQLite/Prisma 的 BigInt 序列化缺失，删掉会导致登录 500；补丁不可删
PG Json 字段存为 String放弃原生 Json 类型应用层手动序列化，规避驱动差异，保持跨库一致
SSE 鉴权用 ?token=不在 header 传 JWTEventSource 不支持自定义 header，URL 查询参数承载令牌
种子脚本按 code upsert禁止"有数据就跳过"保证预置数据可重复运行、幂等更新
训练走 Python worker引入 child_process 而非纯 JS 训练重型拟合用 Python 生态，推理仍回零依赖 JS，训推同构
MCP 自实现零依赖不引官方 SDK保持"零依赖边缘"一致性，减小攻击面与体积

12安全与合规

  • 认证与授权：JWT + Bearer + RBAC 四级（含 MANAGER 等角色），敏感操作（计算健康分、触发训练、执行推理）受角色约束。
  • 多租户隔离：架构级 tenantId 强制过滤（见 §8）。
  • 密钥管理：真实 .env 与密钥从不进 git 历史；.gitignore 隔离 .env / *.db / 密钥 / .workbuddy；部署密码经环境变量（如 CLMX_SSH_PASS）注入，不落仓库。
  • 漏洞披露：设 SECURITY.md，提供私域报告通道，避免公开 issue 提前暴露风险。
  • 依赖安全：dependabot.yml 对前后端 npm、Python、github-actions 周级自动更新。
开源安全审计结论：仓库历史中无真实密钥泄露；发布文件（LICENSE/README/社区健康文件）均经审计后入库。

15结语

CLMX 不是又一个"更聪明的仪表盘"。它把工业 AI 从"训练一个模型"升级为"运营一座模型工厂"——用 AI 原生接入生成器消化接入成本，用零依赖边缘推理守住运行边界，用北向 MCP 把能力开放给外部智能体，用半智能体闭环让平台自身参与决策。

我们以 MIT 协议把整套平台开源，既是对"工业互联网 AI 普惠"的承诺，也欢迎社区共建接入模板、模型算法与资产市场。模型工厂的门，已经打开。

如何参与：① 在 GitHub/Gitee 提 Issue 与 PR；② 用接入生成器贡献设备模板到资产市场；③ 基于 MCP 工具构建你的工业智能体；④ 在 Discussions 分享你的落地实践。
