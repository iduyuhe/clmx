# CLMX 真实设备接入对接文档

> 适用对象：设备侧 / 系统集成工程师
> 版本：阶段5（MQTT + OPC-UA + HTTP 推送）
> 更新：2026-07-15

CLMX 支持四类工业设备/系统接入，把实时遥测写入平台的 `SensorData`，并参与**租户隔离**与**存储配额**管控。

| 协议 | 适配器进程 | 默认端点 | 适用场景 |
|------|-----------|----------|----------|
| **MQTT** | `clmx-mqtt`（aedes 自托管 broker） | `43.153.172.52:1883` | 物联网网关、PLC 上云、自建边缘采集 |
| **OPC-UA** | `clmx-opcua`（node-opcua 客户端） | 你的 OPC-UA 服务器地址 | 工厂 SCADA / MES / 传统 OPC 服务器 |
| **HTTP 推送** | 主 API 服务（`/api/ingest/telemetry`） | `https://<域名>/api/ingest/telemetry` | 边缘盒子 / SCADA 的 REST 上报、第三方系统对接、本地联调 |
| **Modbus** 🔥 | `clmx-modbus`（modbus-serial 客户端） | `modbus://host:502` |  PLC、传感器、仪表、变频器（TCP 或 RS-485 RTU） |

---

## 一、通用规则（三种协议都适用）

1. **租户隔离**：每条数据都必须能定位到「传感器 → 设备 → 租户」。MQTT 通过主题路径 `clmx/<tenantId>/<deviceCode>/telemetry` 携带租户与设备；OPC-UA 通过「节点映射 NodeId → SensorId」隐含归属。写入时系统会校验传感器存在且属于当前租户；HTTP 推送通过 API Key 鉴权获得租户身份，并校验 sensorId / deviceCode 确属该租户。
2. **负载格式**：数值统一为 JSON，字段至少包含 `value`（数字）。
   - MQTT：`{"sensorId":"<传感器ID>","value":12.3}` 或 `{"deviceCode":"PUMP-001","sensorChannel":"temp","value":12.3}`
   - OPC-UA：由适配器自动取节点数值写入映射的 `sensorId`。
3. **存储配额**：每次摄入都会累加租户 `storageUsed`（按数据点计）。达到套餐上限（TRIAL 50 / FREE 1e6 / PRO 2e7 / ENTERPRISE 5e8）后，新数据将被拒绝（HTTP 429）。可在「系统设置 → 用量与配额」查看剩余额度。
4. **质量字段**：可选 `quality`（默认 `GOOD`），`timestamp` 可选（默认服务器时间）。

## 二、MQTT 接入

### 2.1 连接信息
- **Broker 地址**：`43.153.172.52:1883`（TCP，腾讯云安全组已放行）
- **主题**：`clmx/<tenantId>/<deviceCode>/telemetry`
  - `tenantId`：CLMX 租户 ID（后台「系统设置 → 品牌定制」所在租户）
  - `deviceCode`：在 CLMX「设备管理」中创建设备时的编码

### 2.2 上报示例（Python）

```bash
pip install paho-mqtt
```

```python
import paho.mqtt.client as mqtt
import json, time

BROKER = "43.153.172.52"
PORT   = 1883
TENANT = "cmr0p1zf30000bhv5cysz6hj3"   # 替换为你的 tenantId
DEVICE = "PUMP-001"                    # 替换为你的 deviceCode

client = mqtt.Client()
client.connect(BROKER, PORT, 60)
client.loop_start()

topic = f"clmx/{TENANT}/{DEVICE}/telemetry"
while True:
    payload = {"sensorId": "<传感器ID>", "value": 42.0, "quality": "GOOD"}
    client.publish(topic, json.dumps(payload), qos=0)
    time.sleep(1)
```

### 2.3 常见问题
- **连不上 1883**：确认腾讯云安全组已放行 TCP 1883；本地防火墙放行。
- **数据未入库**：检查 `sensorId` / `deviceCode` 是否在 CLMX 中真实存在；查看 `pm2 logs clmx-mqtt`。
- **429 报错**：存储配额耗尽，清理历史数据或升级套餐。

## 三、OPC-UA 接入

### 3.1 部署与配置
OPC-UA 适配器以独立进程 `clmx-opcua` 运行，连接**你方**的 OPC-UA 服务器。

1. 在服务器 `pm2` 中启动（部署脚本已就绪）：
   ```bash
   set CLMX_SSH_PASS=<密码> && python deploy/run_opcua_deploy.py
   ```
2. 配置节点映射，编辑 `/opt/clmx/server/opcua_map.json`：
   ```json
   [
     { "nodeId": "ns=2;s=PUMP-001.Temp",      "sensorId": "cmr1b8tu00003mh97wlqbdyjy" },
     { "nodeId": "ns=2;s=PUMP-001.Vibration", "sensorId": "<另一传感器ID>" }
   ]
   ```
   - `nodeId`：你在 OPC-UA 服务器上暴露的节点标识。
   - `sensorId`：CLMX「设备管理 → 传感器」中的传感器 ID。
3. 配置环境变量（写入 `/opt/clmx/server/.env` 或 pm2 `env`，重启进程生效）：
   ```
   OPCUA_ENDPOINT=opc.tcp://<你的OPC-UA服务器>:4840
   OPCUA_MAP_FILE=/opt/clmx/server/opcua_map.json
   # 可选：OPCUA_USERNAME / OPCUA_PASSWORD
   ```
4. 重新以订阅模式启动：`pm2 restart clmx-opcua --node-args=" "` 并以 `--` 无参数运行（去掉 `--selftest`）。

### 3.2 端到端自检
- 摄入链路：`node scripts/opcua_ingest.cjs --selftest`（直连 PG 验证写入）。
- 全链路（内置 OPC-UA 服务器）：`node scripts/opcua_ingest.cjs --mock`。

### 3.3 常见问题
- **node-opcua 未安装**：部署脚本会自动 `npm install node-opcua`。
- **节点读不到值**：确认 `nodeId` 拼写、命名空间 `ns=` 正确；用 UaExpert 等客户端先验证可读。
- **非数值被跳过**：适配器只摄入数值类型，字符串/布尔节点会被忽略并打日志。

## 四、HTTP 推送接入

适合边缘盒子、SCADA 的 REST 上报，或第三方系统直接对接，也是本地联调最快捷的方式。HTTP 接入由 CLMX 主 API 服务承载，**无需独立进程**。

### 4.1 端点与鉴权
- **端点**：`POST /api/ingest/telemetry`
  - 生产：`https://<你的域名或IP>/api/ingest/telemetry`（经 nginx 3003 反代）
  - 本地：`http://localhost:5173/api/ingest/telemetry`（经 Vite 代理到 3002）
- **鉴权**：复用租户 **API Key**（在「部署 → API 密钥」中创建）。三种携带方式任选其一：
  - 请求头 `x-api-key: <你的APIKey>`
  - `Authorization: Bearer <你的APIKey>`
  - 查询参数 `?api_key=<你的APIKey>`
- 服务端对明文做 SHA-256 后与 `ApiKey.keyHash` 比对，得到租户身份。

### 4.2 负载格式
单条对象 **或** 对象数组（批量上报）：

```json
{ "sensorId": "<传感器ID>", "value": 42.0, "quality": "GOOD", "timestamp": "2026-07-15T08:00:00Z" }
```

或按设备定位（无需知道 sensorId）：

```json
{ "deviceCode": "PUMP-001", "sensorChannel": "temp", "value": 42.0 }
```

- `sensorId` 与 `deviceCode + sensorChannel` 二选一；批量时可混用。
- `value` 必填（数字）；`timestamp`、`quality` 可选（默认服务器时间 / `GOOD`）。

### 4.3 响应
```json
{ "success": true, "data": { "accepted": 1, "written": 1, "skipped": 0, "errors": [] } }
```
- `written`：成功写入条数；`skipped`：跳过条数（含无权限 / 未找到 / 配额耗尽）。

### 4.4 上报示例

**curl**
```bash
curl -X POST "https://<域名>/api/ingest/telemetry" \
  -H "x-api-key: <你的APIKey>" \
  -H "Content-Type: application/json" \
  -d '{"deviceCode":"PUMP-001","sensorChannel":"temp","value":42.0}'
```

**Python（requests）**
```python
import requests
resp = requests.post(
    "https://<域名>/api/ingest/telemetry",
    headers={"x-api-key": "<你的APIKey>"},
    json={"deviceCode": "PUMP-001", "sensorChannel": "temp", "value": 42.0},
)
print(resp.json())
```

**批量**
```python
requests.post(url, headers=H, json=[
    {"sensorId": "id-1", "value": 12.3},
    {"sensorId": "id-2", "value": 9.8, "quality": "GOOD"},
])
```

### 4.5 安全与配额
- **租户隔离**：API Key 决定租户身份；`sensorId` 路径会校验该传感器确属此租户，跨租户写入将被拒绝（响应 `skipped` + 无权限提示）。`deviceCode` 路径按 `tenantId + code` 定位，天然隔离。
- **存储配额**：与 MQTT / OPC-UA 完全一致，超额返回 429。

## 五、Modbus 接入（新增）

### 5.1 连接信息

| 项目 | 说明 |
|------|------|
| 适配器 | `server/scripts/modbus_ingest.cjs`（独立进程，pm2 常驻） |
| 协议 | Modbus TCP（默认端口 502） / Modbus RTU（RS-485 串口） |
| 环境变量 | `MODBUS_ENDPOINT`、`MODBUS_MAP_FILE`、`MODBUS_SLAVE_ID`（默认 1）、`MODBUS_INTERVAL_MS`（默认 5000） |

### 5.2 映射文件

创建一个 JSON 文件，将 Modbus 寄存器地址映射到 CLMX 传感器 ID：

```json
[
  { "sensorId": "<sensor-uuid-from-clmx>", "address": 0, "type": "holding", "length": 1, "scale": 0.1 },
  { "sensorId": "<sensor-uuid>", "address": 2, "type": "input", "length": 2, "scale": 1 }
]
```

- `type`: `holding`（保持寄存器，FC03）或 `input`（输入寄存器，FC04）
- `length`: 1（16 位整数）或 2（32 位 IEEE 754 浮点，大端）
- `scale`: 缩放系数，最终值 = raw × scale

### 5.3 运维

```bash
# 自检（无需真实设备）
cd /opt/clmx/server && node scripts/modbus_ingest.cjs --selftest

# 常驻运行（替换 /path/to/map.json 为你的映射文件路径）
MODBUS_ENDPOINT=modbus://192.168.1.100:502 \
MODBUS_MAP_FILE=/path/to/map.json \
pm2 start scripts/modbus_ingest.cjs --name clmx-modbus

pm2 save
```

## 六、运维命令

```bash
pm2 status                 # 查看 clmx / clmx-mqtt / clmx-opcua 状态
pm2 logs clmx-mqtt         # MQTT 摄入日志
pm2 logs clmx-opcua        # OPC-UA 摄入日志
pm2 restart clmx-mqtt      # 重启 MQTT 适配器
pm2 restart clmx-opcua     # 重启 OPC-UA 适配器
```

所有适配器进程均为 `pm2 save` 落盘，服务器重启后自动拉起。
