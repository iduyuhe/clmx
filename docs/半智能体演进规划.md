# CLMX 半智能体演进规划

> 决策日期：2026-08-07（杜总授权推进）
> 目标：将 CLMX 从「人驱动工具」（智能化成熟度第 1-2 档）提升到「半智能体」（第 3 档）—— 感知 → 决策 → 处置闭环。
> 原则：不与「零依赖边缘 JS 推理」底座冲突；不盲目追全自主智能体 / 大模型微调。

---

## 一、现状基线

| 维度 | 现状 | 说明 |
|------|------|------|
| 模型智能（A 类） | ✅ 已具备 | 工业时序无监督异常检测 + NLP 朴素贝叶斯分类，纯 JS 推理 |
| 平台自身智能（B 类） | ❌ 缺失 | 人传数据、人点训练、人看结果、人决定怎么办 |
| 自动建模（AutoML） | ❌ 缺失 | 特征/算法/阈值由人定 |
| 自然语言交互 | ❌ 缺失 | 必须懂按钮才能操作 |
| 自动决策闭环 | ❌ 缺失 | 检测到异常不会自动处置 |
| 自主智能体 | ❌ 很远 | 无自主规划/跨系统执行 |

---

## 二、演进能力清单（按优先级）

### P0-1 自动基线 / 自动告警阈值　【工作量：小】
- **功能**：基于设备历史遥测自动计算告警阈值（均值 ± k·标准差 / 百分位法），替代人工拍脑袋设阈值；健康分规则引擎接入自动基线。
- **用户价值**：不懂算法也能用；阈值随数据自适配，误报率下降。
- **依赖**：SensorData 历史库（已有）。
- **实现要点**：
  - 后端 `server/src/modules/health/` 新增 `computeBaseline(sensorId, window)` 统计服务。
  - 设备/传感器配置页增加「自动基线」开关，默认开启。
  - 阈值存回 Sensor 或独立 Baseline 表（tenantId 隔离）。

### P0-2 异常自动处置闭环　【工作量：中 · 核心】
- **功能**：健康分低于阈值 / 模型判定异常 → 自动创建工单（WorkOrder）+ 触发通知（复用已上线的 AlertChannel：站内信/Webhook/企微）。
- **用户价值**：从「看到告警」到「自动派单」，平台第一次「自己动手」，是半智能体的标志性能力。
- **依赖**：需新建 `WorkOrder` 模型 + 前端工单页；AlertChannel 已上线可直接复用。
- **实现要点**：
  - schema 增加 `WorkOrder`（tenantId, deviceId, sensorId, severity, status, assignee, description）。
  - `health` 评分写入后触发 `createWorkOrderIfNeeded()`（异步，防风暴：同设备同异常 N 分钟内不重复建单）。
  - 前端新增「工单」菜单 + 列表/详情/状态流转页。

### P1-1 自然语言交互入口　【工作量：中】
- **功能**：对话框用话术操作平台（如「查 3 号机床健康」「训练电机振动模型」「最近有哪些异常」）。
- **用户价值**：非技术用户零门槛上手，产品显得「聪明」。
- **依赖**：无外部大模型（保持零依赖）；用规则 + 现有 NLP 分词/意图解析。
- **实现要点**：
  - 后端 `server/src/modules/nl-command/` 意图解析（正则 + 关键词槽位填充）→ 路由到现有 API。
  - 前端 `ChatCommand` 悬浮组件，对接 `/api/nl-command`。
  - 仅覆盖高频只读/触发指令，不替代完整 UI。

### P1-2 训练结果自动解读　【工作量：小】
- **功能**：训练完成后自动生成人话摘要（样本数、任务类型、关键指标、是否可用、建议下一步）。
- **用户价值**：人不用看曲线也懂模型好坏，降低决策门槛。
- **依赖**：TrainingJob / ModelVersion 已有指标字段。
- **实现要点**：
  - `training` 模块训练完成钩子调用 `summarizeTraining(job)` 生成 `summary` 文本字段。
  - 训练详情页顶部展示摘要卡片。

## 三、暂不做（避免量级错配）

| 项目 | 原因 |
|------|------|
| 全自主智能体（跨系统自演化） | 超出当前产品边界，且与边缘零依赖底座张力大 |
| 大模型微调 / LLM Agent | 需要 GPU/大模型服务，破坏「纯 JS 边缘推理」护城河 |
| 全自动 AutoML（自动特征+选型+超参搜索） | 投入大、边际感知弱，先用自动基线替代 |

---

## 四、建议启动顺序

1. **P0-1 自动基线阈值**（最小风险，纯算法，立刻提升体验）
2. **P0-2 异常自动处置闭环**（核心标志能力，需建模型+前端）
3. **P1-2 训练结果自动解读**（小投入，强感知）
4. **P1-1 自然语言交互入口**（最后做，依赖前三项的数据接口成熟）

> 每完成一项即部署上线并跑 e2e，保持「小步快跑、线上验证」节奏（沿用 deploy/deploy_saas.py + PM2）。
