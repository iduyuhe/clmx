我们开源了 CLMX：把工业 AI 的门槛降下来

过去半年，我们一直在做一件事：让一家普通工厂，也能用上「属于自己的工业 AI」——不用养算法团队、不用堆 GPU、不用从零造平台。今天，我们把这套系统 CLMX 正式开源了。

一、CLMX 是什么

一句话：CLMX 是一个面向工业互联网的垂类 AI 模型训练、推理与能力开放平台。

更准确地说，CLMX 不是某一个"智能模型"，也不是一个"聊天机器人"。它是一座模型工厂——你给它工业设备的运行数据，它帮你训练出专属于你的预测性维修模型；你给它一段设备文档，它自动生成采集驱动把数据接进来；你用自然语言就能指挥它做健康分评估、跑推理、触发训练。

它的三层定位可以这么理解：

🏭 表 · 工业设备预防性维修
设备健康分、异常告警、预测性维护——这是用户直接看到的业务价值。
🧠 里 · NLP / ML 模型平台
无监督异常检测、零依赖中文文本分类、模型训练与推理底座。
☁️ 底座 · SaaS 多租户交付
行级数据隔离、配额计费、白标，一套平台服务多家客户。

二、我们看到了什么痛点

做工业 AI 这些年，我们反复撞上"四道坎"：

  • 接入即地狱：上千种设备协议、五花八门的字段，接数据往往比建模本身还累。
  • 标注稀缺：工业故障样本极少，有监督学习在车间里经常"无米下锅"。
  • 边缘跑不动：动辄上 G 的深度学习框架，根本塞不进现场的边缘盒子。
  • 平台不智能：很多"平台"只是把工具堆在一起，决策还得人拍脑袋。

CLMX 的每一条设计，几乎都是被这四道坎"逼"出来的。

三、四大核心能力

1半智能体闭环

我们不做"全自主智能体"（那与零依赖边缘底座冲突），而是落地第 3 档"半智能体"：用自然语言下达指令 → 自动建基线/算阈值 → 异常自动处置 → 训练结果自动解读。感知-决策-处置形成闭环，人只在关键节点把关。

2AI 原生接入生成器

这是应对"接入即地狱"的杀手锏。你丢给它一份设备文档、一段样本数据或一句中文描述，它自动提取测点、生成物模型，并产出一段零依赖的 JavaScript 采集驱动，再用沙箱自测跑通后才交付。接线员也能在几分钟内接好一台新设备。

3北向 MCP 能力开放

CLMX 不只是"被用的平台"，更是"可被编排的能力"。我们实现了零依赖的 JSON-RPC（MCP 协议）服务端，对外封装了 10 个工具——自然语言指令、设备列表、健康看板、触发训练、跑推理等，让外部 AI 智能体可以直接调度 CLMX 的能力。

4多租户 SaaS 隔离

所有 CRUD 强制带 tenantId 行级隔离，预置数据按 tenantId IS NULL 共享，JWT 注入身份与角色。一套平台，安全地服务多家客户。

四、技术底座的两个"护城河"

🔧 零依赖
核心推理不依赖任何深度学习框架，纯 JavaScript 即可在边缘盒子跑起来。部署体积以 KB 计，而不是 GB。
🔁 训推同构
训练端和推理端用同一套代码与数学定义，模型从平台出来就能直接在现场跑，不存在"训得好推不动"的断层。
我们用"无监督异常检测"解决标注稀缺，用"朴素贝叶斯零依赖 NLP"解决边缘跑不动——务实，但不取巧。
